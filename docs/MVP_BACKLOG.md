## 2. Приёмка по задачам

### B00 — проверить среду и bootstrap

Подтверждено разработчиком: минимальный мод собран в Docker с .NET SDK 10/net10.0 и успешно загружен в RimWorld 1.7 unstable с WaylithCLR. Независимый протокол проверки, build manifest и остальные критерии B00/B01 пока не оформлены.

Критерии полного завершения: зафиксированы точный game build, branch, runtime, SDK, фактические пути reference DLL, их версии и SHA-256, runtimeconfig/deps и assembly metadata (либо их отсутствие); установлен путь Player.log, сохранён короткий очищенный протокол bootstrap. Секреты и игровые DLL не попали в git или отчёт. Эти сведения пока pending; B00 полностью не закрыта.

Проверка: разработчик предоставляет фактический manifest и очищенный протокол; агент сверяет только явно подключённые references. Проверки Def, HediffComp, Scribe, UI, Jobs и stat выполняются в задачах-владельцах B02–B07 по TECHNICAL_DESIGN §2, а не блокируют весь bootstrap.

### B01 — воспроизводимая сборка

Подтверждено: существуют Source/PathOfCultivation.csproj с net10.0, минимальный класс мода и About/About.xml с supportedVersions=1.7; сборка в Docker и загрузка минимального мода прошли. В проекте нет обязательных DLC, Harmony или VEF. Это ещё не полная приёмка B01.

Критерии полного завершения: закреплены точные SDK/image/packages (для используемых packages); build создаёт только собственные DLL; metadata загружается один раз, supportedVersions отражает тест. Pending: pin SDK и digest образа, clean build на подготовленном offline cache, проверка содержимого output, запуск Core+мод без DLC с новым главным меню без красных ошибок и повтор сборки в новом контейнере с теми же refs. Не запускать API в network-none build контейнере.

Минимальные условия перехода к B02: доступны локальные references, проект net10.0 и metadata; подтверждены сборка в Docker и загрузка минимального мода. Bootstrap-условия подтверждены разработчиком; недоступность refs в конкретной сессии блокирует только проверки, которым они нужны. Полного закрытия B00/B01 для начала B02 не требуется: manifest остаётся за B00, воспроизводимость и упаковочный каркас — за B01; они обязательны до начала B03. Зависимость B02 от B01 означает этот минимальный bootstrap, а не предварительную проверку всех API. Def API проверяется при B02; остальные API — при своих задачах.

B02 целиком не закрыта: приведённые ниже требования и проверки не считаются выполненными на основании проверки загрузки B02.1.

Готово: POC_BodyTemperingI, POC_BodyTemperingII, POC_IronBody; переход только I→II; caps=100/20 на I и 0/30 на II; отрицательные/некорректные значения не проходят validation. Progress и Qi отдельны.

Автоматизированные проверки B02 (общие правила и порядок работы при отсутствии инфраструктуры — [CODEX_GUIDELINES §7](CODEX_GUIDELINES.md#7-проверки-в-рабочем-цикле-и-перед-коммитом)):

- Расчёты Progress/Qi: cap, zero delta, delta partition (одинаковое суммарное время при разном разбиении delta), независимость ресурсов. Проверить нулевые значения, достижение и превышение cap начислением; заполненный Qi не блокирует рост Progress, заполненный Progress не блокирует Qi в пределах согласованных правил.
- Валидация Def: invalid definitions по согласованным ограничениям. Принятый B02.1 не переоткрывается из-за новой политики; оставшиеся проверки B02 сохраняются и не считаются выполненными по результатам его загрузки.
- Условия перехода I→II: недостаток Ци и Progress, точные пороги и достаточные значения по GDD §4; отсутствие следующего Realm на II. Проверки условий не подменяют проверку итогового применения результата.

Эти группы относятся к соответствующим частям B02 по поведению и не задают новую нумерацию срезов. До реализации тестов уточнить не согласованную для конкретного расчёта семантику ошибочных входов, расходования ресурсов и конечной ступени; тесты не вводят новые правила.

Проверка адаптера/игры: во временном XML заменить threshold и получить новый результат без изменения C#; вернуть данные перед commit. Загрузка Defs и разрешение ссылок проверяются в RimWorld отдельно от unit tests; способ автоматической проверки с зависимостью от Verse требует подтверждённой инфраструктуры (см. [TECHNICAL_DESIGN §12](TECHNICAL_DESIGN.md#12-проверки-и-выпуск)).

### B03 — состояние и сохранения

Готово: обычная допущенная пешка по команде получает ровно один state Hediff; schemaVersion=1; Realm/Progress/Qi/techniques восстанавливаются; unknown ID сохраняется и диагностируется; derived bonus не умножается.

Проверка: присвоить тестовые 37 Progress и 12 Qi; сохранить, выйти из игры, загрузить; значения точны в пределах принятого числового epsilon. Повторить 10 save/reload, начать путь второй раз; state всё ещё один. Установка в старый vanilla save позволяет войти новой командой.

Проверка миграции: отсутствующее поле получает безопасное значение; неизвестная техника dormant; неизвестная ступень блокирует прогрессию без тихого сброса; более новая schema не изменяется. Реальные fixtures готовятся при реализации.

### B04 — вход и окно

Готово: CultivationSpot строится без исследования/ресурсов, выбранный взрослый колонист открывает окно через его меню. Видны Realm, Progress и Qi, IronBody, причина блокировки, предел версии II. «Начать путь» идемпотентно.

Проверка: новый игрок на чистом запуске находит место и вход без Dev Mode; проверить обычный размер окна и масштаб UI, русские/английские строки. Животное, механоид и недопущенная пешка не получают state. Нет ссылки на отключённый DLC.

### B05 — медитация

Готово: ограниченная сессия 2 часа; +2 Progress и +5 Qi за выполненный час; рост только у места и только во время actual toil. Потребности работают; сессия прекращается при еде<30% или отдыхе<25%, draft и потере места. UI обновляется без сканирования всех Pawn.

Проверка: Qi=0/Progress=0; одна полная сессия даёт Progress=4, Qi=10. При Qi=19 сессия поднимает Qi до20, но Progress продолжает расти. При Progress=99 и Qi=0 Progress=100, Qi растёт до10. Обе границы работают независимо.

Проверить отмену через час: около +2/+5, без начисления остатка. Сравнить одинаковое число ticks на 1x и 3x; на паузе значения стоят. Занятое/недоступное место даёт понятную ошибку; призыв прекращает занятие немедленно. На II возвращается только Qi; полный запас не назначает бесполезную сессию.

### B06 — гарантированный прорыв

Готово: на I при Progress=100, Qi≥15 назначается Job на 1 час; после завершения II, Progress=0, Qi минус15, cap=30. На II кнопка недоступна. Повторный вызов не меняет результат.

Проверка: отдельно Progress=99, Qi=20; Progress=100, Qi=14; полноценные условия 100/20 → результат II/0/5. При 100/15 → II/0/0. Draft за миг до завершения не выдаёт ступень и не тратит Ци.

Сохранить во время подготовки, загрузить; допускается корректное продолжение либо заранее документированная безопасная отмена. Любой вариант даёт не более одной награды и одного списания. Дважды нажать кнопку; получить один Job. На I недопущенная пешка не может завершить прорыв.

### B07 — свиток и «Железное тело»

Готово: обычный игрок изготавливает свиток по базовому рецепту за 10 дерева; чтение 2 часа; один экземпляр расходуется при завершении; знание одно; bonus один, +0.10 к подтверждённому стату blunt armor. Нет изменения HP или глобальной обработки damage.

Проверка: изготовить предмет без Dev Mode и DLC; назначить чтение; проверить окончание, отмену, уничтожение цели и недоступный предмет. Из стопки 3 свитков после чтения остаётся2. Знающая пешка не расходует новый экземпляр.

Сравнить числовой stat до/после на одной пешке без иных изменений, показать offset в breakdown. Save/reload и прорыв сохраняют ровно один эффект. Две пешки не читают один зарезервированный экземпляр одновременно.

### B08 — регрессия и плейтест

Готово: протокол содержит build, commit, mod list, steps, expected/actual. Чистый запуск без DLC, новый save, добавление в vanilla save и baseline public save проверены. Нет новых красных ошибок, повреждения save и бесконечных Jobs.

Проверить минимум:
- полный путь от нового колониста до II и изученной техники;
- два культиватора одновременно, разные значения;
- save во время медитации, чтения, прорыва;
- caravan/off-map и возврат, death/resurrection через Dev Mode;
- разрушение места, draft, starvation/rest cancellation;
- unknown IDs/migration и duplicate effects;
- восстановление после следующего запуска процесса;
- один smoke с установленными DLC, но отключёнными integrations.

Плейтест без Dev Mode: 10–15 игровых дней при примерно4 часах практики в день. Измерить реальные часы практики, потребности, хозяйственную цену и удобство. Отладочное ускорение служит regression, но не заменяет баланс.

Производительность: на одном save и скорости сравнить без мода/с модом, записать ticks/sec и количество пешек. При доступном profiler посмотреть Jobs/effects. При разбросе повторить; не объявлять фиксированный процент ускорения. Должны отсутствовать новые глобальные обходы и массовые allocations каждый tick.

### B09 — выпуск

Готово: архив содержит metadata, проверенные DLL/Def, нужные textures/localization; инструкция описывает установку, вход, изготовление свитка, предел версии, проверенный build и ограничения удаления/downgrade. Secret/refs/game DLL/package caches отсутствуют. License собственного кода выбрана человеком.

Проверка: распаковать архив в отдельный локальный Mods каталог, запустить и повторить smoke. Проверить все относительные пути и registry classes. Только затем final tag v0.1.0. Публикация Workshop не выполняется агентом без отдельного поручения.

## 3. Definition of Done 0.1.0

Игрок на обычном старте без DLC выполняет полный цикл; все обязательные критерии выше пройдены; state восстанавливается после нового запуска; никакая техника или прорыв не дублирует награду. RC имеет отдельный проверенный commit и game build.

Приёмка учитывает относящиеся к задаче проверки по [CODEX_GUIDELINES §7](CODEX_GUIDELINES.md#7-проверки-в-рабочем-цикле-и-перед-коммитом); конкретные сценарии заданы выше. Успешная компиляция не закрывает B08.

## 5. Архитектурные ограничения для будущих животных

Дополнение не добавляет задач, часов или игровых критериев в B00–B09. MVP 0.1.0 и цель 10 ноября 2026 года неизменны. Духовные звери, их пробуждение, практика, UI, дикая генерация, эволюция, ядра, договоры и DLC остаются за пределами backlog.

В рамках обычного review B02/B03: CultivatorState и расчёты caps/переходов не должны требовать Humanlike/колониста, чтения книг или человеческого возраста; эти ограничения принадлежат адаптеру команд. HediffComp_Cultivator остаётся единственным владельцем. Не создавать AnimalCultivatorState, заглушки species framework, поля будущих договоров, animal tick или новые Def ради расширяемости.

В B04 сохраняется прежний отрицательный тест: животное не начинает путь и не получает человеческие команды. Эта проверка относится к политике 0.1.0, а не к запрету животным в общей математической модели. Реальные animal API, animal saves и нагрузочные тесты SB0 откладываются до 0.4.1 и не блокируют B00–B09.

## 6. Ambient Qi не входит в 0.1.0

Задачи B00–B09, приёмка, 39–49 часов плюс прежний резерв и цель 10 ноября 2026 года остаются неизменными. В MVP Qi означает Personal Qi. Насыщенность среды, Affinity/Tolerance, Spiritual Strain, зоны/источники/подавители, overlay, новые растения и DLC-адаптеры не добавляются даже как отключённые реализации.

В review сохранить только границу ответственности: Core не ищет карту, UI не владеет состоянием; CultivatorState не содержит spatial grid или ambient reservoir. Не вводить сейчас MapComponent, пустые callbacks, environment-поля/интерфейсы, новые schema и дополнительные игровые тесты ради будущей 0.4.2. Текущие фиксированные rates, гарантированный прорыв и независимые caps остаются прежними. AQ0 и тесты воздействия относятся к отдельному этапу после MVP.
